The Challenge

Organizations invest heavily in data platforms, but the gap between having data and having trusted, consistent answers remains wide. Business users ask the same questions in different ways, get different answers from different tools, and lose confidence in the data. The root cause is not the data itself — it is the absence of a governed semantic layer that encodes what the data means, how metrics are calculated, and how tables relate to each other.

What Is Genie Ontology?

Genie Ontology is the combination of Unity Catalog Semantics — metric views, Pages, domains, descriptions, and certification — with certified domain Genie Agents. Together, they form a governed knowledge layer that makes Genie One, Genie Code, dashboards, and downstream applications accurate and trustworthy.

The SDK automates the creation of this entire layer from your existing Unity Catalog assets.

10 Automated Waves

The SDK executes through a series of orchestrated waves — each producing versioned artifacts in your repository. Every wave builds on the outputs of previous waves, creating a complete, auditable trail from raw data to deployed agents.

0
Initialization
Validates your inputs, creates a feature branch, and scaffolds the project structure.
1
Domain Research
Researches your domain — industry terminology, standard KPIs, regulatory context, benchmarks — and proposes a domain and subdomain structure.
2
Context Extraction
Parses your supplemental materials — business requirements, data dictionaries, PowerBI and Tableau exports — extracting measure definitions, join relationships, and business rules.
3
Deep Data Analysis
Profiles every source table: structure, integrity, quality, lineage, usage patterns, grain, primary and foreign keys, cardinality, and volume.
4
Metric View Synthesis
Synthesizes all context into parameterized metric view YAML definitions with semantic metadata, verified joins, and auto-detected materialization for cost optimization.
5
Metric View Registration
Registers every metric view in Unity Catalog using an idempotent forEach pipeline. Runs smoke tests and join cardinality validation.
5.5
UC Pages Registration
Registers glossary terms as UC Pages — the governed business definitions that make your ontology discoverable and self-documenting.
6
Genie Agent Curation
Organizes metric views into certified domain Genie Agents — splitting by subdomain when needed to maximize accuracy and minimize ambiguity.
7
Agent Deployment
Deploys each Genie Agent and validates it can respond to business questions with correct, governed SQL.
8
Tuning & Benchmarking
Generates benchmark questions, runs accuracy tests, and iterates on metric view definitions — tuning the semantic layer first, not the agent, to avoid overfitting.

Design Principles

Metric Views Are Governed Enterprise Assets
Metric views are not just context for AI tools — they are versioned, testable, deterministic business logic that lives in Git and deploys only through CI/CD. They can be used and tested outside any AI agent or chat interface.
Tune the Semantic Layer First, Not the Agent
Adding too many specific instructions or example SQL queries to a Genie Agent is like overfitting a machine learning model. The SDK prioritizes metric view synonyms, comments, and measures as the first lever for accuracy. Agent-specific instructions are a last resort.
Context First
Business requirements, existing validated reports, industry research, and deep data profiling all feed into the metric view definitions before a single line of YAML is written. The ontology is grounded in real-world business language, not just column names.
Zero Hardcoding
Nothing in the pipeline is hardcoded — catalog names, schema names, table references, everything is parameterized. The catalog is the environment discriminator. The same commit promotes across environments with only target configuration changing.
Materialization for Cost Optimization
The SDK auto-detects metric views that would benefit from materialization based on source table volume, join complexity, and estimated query frequency. The first deployment is already cost-optimized.
Full Regeneration Is Safe
The pipeline is idempotent. Re-running it converges on the desired state without outage windows or manual cleanup. This makes ongoing maintenance straightforward — update the inputs and re-run.
