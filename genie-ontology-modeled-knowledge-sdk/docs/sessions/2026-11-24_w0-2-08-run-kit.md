## Decisions
* `context_files` = `sdk_config.json`, `PROJECT_MEMORY.md`, `docs/inputs_report.md` (per plan).
* `plan_file` values are `plans/<file>.md`, because scaffold copies `templates/run/*` into `docs/plans/` unchanged. That gives `docs/plans/plans/*.md`, which matches `plans_dir: docs/plans`. `PROJECT_MEMORY.md` goes to the project root (plan 09).
* Running `register_metric_views` (sessions 06 and 10) and writing UC Pages (07) are side effects that tier-1 implied approvals do not cover. They are listed as session `authorizations` (tier 2, owner-approved through the manifest the owner scaffolds and sets up). Domain creation stays opt-in and is not authorized.
* Wave 4 runs pages (07) and agent curation (08) in parallel. Neither deploys.
* Tuning uses a single `docs/tuning/benchmark_questions.yml` with `agent:<name>` tags (the ontology-tuning skill defers to the run kit).
* No runtime_targets/converge. Deployed resource names depend on the user/dev prefix and would be workspace-specific. Evidence comes from the session results files, and the integrator reports it as required checks.
